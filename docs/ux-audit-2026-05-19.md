# UX Audit — 2026-05-19 (Claude pass)

Full UX audit of the live app against the original design intent.

- **Audited:** `https://evenly-snowy.vercel.app` (signed in, current prod deploy) at **375×667** and **1280**.
- **Rubric:** `docs/ux-principles.md` (north-star + hard requirements + forbidden patterns + accessibility floor) and `docs/design-system.md` (visual system, per-screen state matrices, decisions of record).
- **Evidence (repo root, gitignored binaries):** `audit-01-home-375.png`, `audit-02-smartscan-375.png`, `audit-03-addexpense-375.png`, `audit-04-settings-375.png`, `audit-05-home-web1280.png`. Accessibility snapshots under `.playwright-mcp/`.
- This is the **Claude pass**. A parallel Codex pass + asset generation is briefed separately; Codex returns implementation instructions for Claude.

## Headline conclusion

The spec's "Stripe register split" (`design-system.md` §2) is the right frame:

- **Working register** (edit forms, lists, settings, empty states) — calm, white, hairline-bordered, well-spaced, **largely on-spec**.
- **Hero register** (Home top card, sign-in) — **badly broken**; this is the dominant prod-readiness gap and the app's first impression.

## P2 — Polish / minor

- Add-expense **date** is a raw `YYYY-MM-DD` text field; defaults to today ✓ but **no one-tap "Yesterday"** (ux-principles forbidden-pattern asks for it).
- **Category chips** (Add expense) lack the leading category-color dot (§3.2 allows it; reinforces color-independence).
- **EmptyState illustration** is a tiny placeholder receipt — acceptable per §12 (M1 placeholders) but in scope for the asset-generation pass.

## Spec-doc defects (the rubric itself)

`design-system.md` contradicts itself: §3 (revised 2026-05-06) defines the accepted **blue** brand (`brand-accent #8FC2FF` / `brand-interactive #2457D6`), but §13 "Decisions of record" + §4.3 still cite the **old purple** (`#A171F5` / `#7C3AED`), and §11/§13 say "single tab Home (M1)" while the app ships Home+Settings. Auditing against a self-contradicting rubric is ambiguous — reconcile §13 / §4.3 / §11 to the §3 revision (separate doc-maintenance task; not a code change).

## On-spec / positives (do not regress)

Smart Scan empty, Add expense, Settings: calm white cards + hairline borders, generous whitespace, single correct headers (post header fix), `brand-interactive` primary buttons, **currency override at top** (✓ ux-principles), **date defaults to today** (✓), **SegmentedControl active = brand-interactive** (✓ §7), 0 console errors throughout. The working register honors the spec.

## Coverage caveats (remaining audit)

Not visually verified this pass and **owned by the Codex pass**: **Split spotlight wizard (C7)** — the most spec-dense screen (spotlight opacity/collapse/auto-advance, §"spotlight wizard"); **Sign-in hero**; **offline / error / loading state matrices** (cannot be forced live).

## Disposition

P0 is a concrete defect (specimen text shipped to prod), not a taste question. Recommended: Claude fixes P0 as a focused correctness pass; P1/P2/C7/sign-in/state-matrices + all design-asset generation (hero image, logo/wordmark, category icon set, empty-state illustrations, skin assets) go to the Codex pass, which returns implementation instructions for Claude.
